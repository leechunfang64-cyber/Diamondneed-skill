# Diamondneed Skill：竞品需求分析与机会判断

这是一个用于 **竞品需求分析、AI 产品调研、小红书选品、虚拟产品选品、SaaS 机会判断** 的 Agent Skill。

它的核心目标不是写一份泛泛的市场分析报告，而是帮助你判断：

> 这个产品/赛道/关键词有没有真实需求？有没有人付费？对手强不强？小团队能不能降维打击？值不值得投入时间做？

最终输出必须落到一个明确决策：

```text
Go Now / Small Bet / Observe / Reject
```

---

## 1. 这个 Skill 适合什么时候用？

当你看到一个产品、AI 工具、关键词、小红书品、虚拟产品、SaaS 点子、市场服务或商业机会时，可以使用这个 skill 做下注前调研。

典型场景：

```text
我发现一个 AI 工具，想判断能不能做。
我看到小红书某个品最近爆了，想判断是不是机会。
我想分析一个竞品，大概估算它能赚多少钱。
我想判断一个关键词有没有需求。
我想知道某个产品有没有付费验证。
我想看这个赛道是不是蓝海。
我想知道对手弱不弱，小团队能不能打。
```

适合分析的对象包括：

```text
AI 产品
AI 工具站
小红书选品
虚拟产品
SaaS 点子
插件 / Chrome Extension
模板产品
知识付费产品
私域产品
服务产品化机会
Fiverr / Upwork 服务
SEO 工具站
内容站 / 资源站
```

---

## 2. 这个 Skill 的核心判断逻辑

这个 skill 会按照以下链路判断一个机会：

```text
需求证据
→ 付费验证
→ 小红书验证
→ 竞品强弱
→ 盈利区间
→ 流量打法
→ 风险反证
→ Go / Small Bet / Observe / Reject
```

它重点关注：

```text
是否有人真实购买
订单速度：24小时 / 48小时 / 一周 / 一个月
小红书笔记爆不爆
评论区有没有购买意图
同行数量和同行强弱
对手是否不专业但依然卖得动
流量是泛流量还是精准流量
是否能自动化交付
是否能复购
是否能沉淀内容、数据、私域、品牌或系统
小团队是否能实现降维打击
```

## 3. 安装与使用方式

### 方式 A：作为 Agent Skill 使用

把整个仓库作为一个 skill 文件夹放到你的 Agent / 编程助手支持的 skills 目录中。

目录结构应保持为：

```text
Diamondneed-skill/
├── SKILL.md
├── README.md
├── references/
│   ├── research-sources.md
│   ├── paid-validation-and-xiaohongshu-framework.md
│   ├── go-no-go-checklist.md
│   ├── revenue-estimation-template.md
│   └── competitor-analysis-rubric.md
└── evals/
    └── evals.json
```

不同 Agent 的 skills 目录位置可能不同。核心原则是：

1. 保留 `SKILL.md` 在 skill 根目录。
2. 保留 `references/` 参考文件。
3. 不要只复制 README，真正触发 skill 的是 `SKILL.md` 里的 frontmatter description。

### 方式 B：作为普通提示词工作流使用

如果你的工具暂时不支持 Agent Skill，也可以直接打开 `SKILL.md`，把其中的流程当作调研提示词使用。

你可以这样对 AI 说：

```text
请按照这个 competitor-demand-research skill 的流程，帮我分析下面这个产品机会：

产品/赛道：{填写产品或赛道}
竞品链接：{可选}
目标用户：{可选}
已知数据：{可选}
我的初步判断：{可选}

请输出 Go / Small Bet / Observe / Reject 决策。
```

## 6. 决策含义

### Go Now

适合：

```text
需求清晰
已有付费验证
对手弱或存在明显切口
流量路径清楚
MVP 能快速做
毛利健康
有复购或资产沉淀空间
```

### Small Bet

适合：

```text
方向不错
有部分需求或付费信号
但成交、流量或竞争仍有不确定
```

动作：先用小红书笔记、落地页、店铺商品页、私域人工交付做低成本验证，不要一开始重仓开发。

### Observe

适合：

```text
方向有意思
但搜索、成交、流量或竞品信号不足
```

动作：加入观察清单，持续看 2-4 周。

### Reject

适合：

```text
需求弱
没有付费信号
流量不可达
竞争过强
成本或风险过高
自己无法理解用户
无法形成长期资产
```

动作：放弃，不要消耗创业注意力。

## 8. 使用原则

这个 skill 的底层原则：

```text
不要因为没人做就以为是蓝海。
不要因为很多人做就以为没机会。
不要因为点赞高就以为能赚钱。
不要因为流量大就以为转化好。
不要因为产品能做就以为值得做。
```

真正值得做的机会通常是：

```text
需求明确
用户已经付费
对手不强
流量可达
成本可控
能自动化交付
能沉淀资产
小团队能降维打击
```

最终目标是从：

```text
会做功能
```

升级到：

```text
会做让用户愿意付费的功能
```
