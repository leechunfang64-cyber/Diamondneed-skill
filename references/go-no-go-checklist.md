# Go / No-Go Checklist

Use this checklist before committing serious time, money, development effort, or content effort to a new product opportunity.

## 1. 必须回答的问题

1. 这个需求真实吗？
2. 用户是谁？
3. 用户在什么场景下需要它？
4. 用户现在怎么解决？
5. 用户愿不愿意付费？
6. 有没有真实购买或订单？
7. 订单是偶发，还是持续？
8. 搜索量是否足够？
9. 有没有平台售卖信号？
10. 有没有竞品已经赚钱？
11. 竞品强不强？
12. 我能不能降维打击？
13. 流量从哪里来？
14. 是泛流量还是精准流量？
15. 小红书内容能不能跑？
16. 24 小时、48 小时、一周、一个月内是否有可观察成交？
17. 同行数量多不多？
18. 同行专业不专业？
19. MVP 多久能做出来？
20. 客服和交付成本高不高？
21. 是否能自动化？
22. 是否能复购？
23. 是否能沉淀内容、数据、私域、品牌或系统？
24. 我是否能亲自体验这个需求？
25. 做完之后是否会形成长期资产？

## 2. 直接否决条件

出现以下情况，原则上不要重仓：

- 看不到真实用户。
- 看不到明确付费信号。
- 只有概念热度，没有实际需求。
- 有流量，但没有购买意图。
- 用户只想白嫖，不愿意付费。
- 流量无法触达。
- 前排全是强品牌、大站、成熟产品。
- 项目需要大量人力客服。
- 交付严重依赖人工。
- 毛利被 API 成本、履约成本或售后成本吃掉。
- 不能复购。
- 不能沉淀资产。
- 自己无法理解用户痛点。
- 只是短期信息差，没有长期壁垒。
- 法律、版权、平台风险过高。
- 做完之后无法形成内容、用户、数据、品牌、私域或流程资产。

## 3. 推荐进入条件

满足越多，越值得做：

- 需求明确。
- 用户搜索意图强。
- 有人在付费。
- 订单在短周期内持续出现。
- 对手少。
- 对手弱。
- 对手内容、页面、客服、私域承接都不专业。
- 对手不专业但依然卖得动。
- 竞品体验差。
- 竞品定价高但服务差。
- 有精准关键词。
- 可以从小红书、SEO、私域、平台流量切入。
- MVP 可以快速做。
- 可以自动化交付。
- 可以复购或持续订阅。
- 可以沉淀数据、模板、内容、用户或品牌。
- 可以形成小团队的降维打击。

## 4. 推荐验证动作

### Small Bet 验证

适合信号不错但不确定的机会：

- 做 3-5 条小红书测试笔记。
- 做一个极简落地页。
- 做一个店铺商品页。
- 用私域或客服手动承接。
- 先人工交付，不急着完整自动化。
- 用 7 天观察咨询、购买、退款、复购和反馈。

### MVP 验证

适合需求清晰、有付费信号的机会：

- 只做核心功能。
- 只服务一个明确人群。
- 只覆盖一个高频场景。
- 保留客服反馈入口。
- 记录用户卡点。
- 观察用户是否愿意持续使用和付费。

### 放大验证

适合已经有订单和可复制流量的机会：

- 扩展内容矩阵。
- 做关键词页面。
- 加私域承接。
- 优化商品页。
- 建立客服 SOP。
- 做复购产品。
- 做自动化交付。
- 计算真实毛利和回本周期。

## 5. 最终决策标准

### Go Now

满足：

- 需求清晰。
- 已有付费验证。
- 对手弱或存在明显切口。
- 流量路径清楚。
- MVP 能快速做。
- 毛利健康。
- 有复购或资产沉淀空间。

### Small Bet

满足：

- 需求看起来成立。
- 有部分付费或强兴趣信号。
- 但成交、流量或竞争仍有不确定。

动作：先做低成本验证，不重仓开发。

### Observe

满足：

- 方向有意思。
- 但搜索、成交、流量或竞品信号不足。

动作：加入观察清单，持续看 2-4 周。

### Reject

满足：

- 需求弱。
- 没有付费信号。
- 流量不可达。
- 竞争过强。
- 成本或风险过高。
- 自己无法理解用户。
- 无法形成长期资产。

动作：放弃，不要消耗创业注意力。
